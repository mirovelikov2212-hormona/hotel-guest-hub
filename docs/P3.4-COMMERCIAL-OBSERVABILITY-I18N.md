# P3.4 — Commercial Observability + BG/EN Control Plane

P3.4 makes the commercial Control Plane operationally readable without adding a second commercial authority.

## Bilingual operator UI

The Control Plane supports `bg` and `en`, defaults to Bulgarian, and preserves the selected language through sign-in, sign-in errors, successful authentication, commercial actions, refreshes, and sign-out.

Only visible presentation is translated. Database status values and API action codes remain canonical English machine identifiers.

## Commercial attention

The page derives an in-app attention queue at read time:

- expired trials;
- trials ending within 1 day;
- trials ending within 3 days;
- trials ending within 7 days;
- pending commercial decisions;
- suspended customers/trials.

No cron, alert-state table, scheduled mutation, or copied commercial state is introduced.

## Commercial history

The Control Plane reads the latest 50 immutable `property_commercial_lifecycle_events` newest-first and displays the latest 12 in the operator timeline.

The read is platform-authority-only, bounded, and does not mutate tenant or commercial state.

## Safety

- no Product Factory activation;
- no commercial transition invoked for validation;
- no backfill;
- no new database migration;
- no browser-side Supabase access;
- existing P3.1 same-origin action API remains the sole commercial mutation path;
- P3.3 runtime entitlement authority is unchanged.
