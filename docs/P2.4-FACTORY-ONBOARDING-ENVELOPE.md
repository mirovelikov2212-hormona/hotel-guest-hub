# P2.4 — Product Factory Onboarding Envelope

Status: **roles + reporting + branding + knowledge + AI permissions + public identity + health gate**

## Goal

P2.4 completes the non-runtime onboarding envelope around the P2.1–P2.3 tenant configuration while keeping both Production and Sandbox inactive and uncertified.

## Resources

For each isolated environment P2.4 creates:

- fail-closed role templates, without users, PINs, passwords or permissions;
- disabled reporting configuration with no recipients;
- placeholder branding configuration;
- placeholder multilingual knowledge configuration;
- explicit AI action permissions with every action disabled;
- reserved guest/QR/staff-QR route identities;
- health/certification state starting at `pending / not_started`.

The factory creates no staff credential and grants no runtime authority.

## Public identities

Production and Sandbox receive separate reserved identities derived from their existing hotel/public slugs. Reservation is not activation. The hotel rows remain inactive and the route identity state remains `reserved` until certification and publication.

## Revision state

A successful transaction creates draft revision 4 for both environments. Validation remains false with `FACTORY_SANDBOX_CERTIFICATION_PENDING` and warning `P2_4_ONBOARDING_ENVELOPE_READY`.

Projection state remains `pending`. No publication state, hotel activation or property lifecycle promotion occurs.

## Idempotency and authority

P2.4 requires the exact P2.3 operational projection lineage and verifies all earlier hashes. One envelope projection is allowed per P2.3 run. Same lineage/hash replays; different hash fails.

Mutation remains same-origin Control Plane only, requires active `super_admin` or `operator`, and uses a service-role-only SECURITY DEFINER RPC which rechecks platform authority.

## Next certification gate

After P2.4 the factory has the full structural onboarding envelope, but it is still deliberately unrunnable. The next phase must certify the Sandbox, harden generic Staff runtime for custom departments, validate the complete revision, and only then permit explicit publication/activation.
