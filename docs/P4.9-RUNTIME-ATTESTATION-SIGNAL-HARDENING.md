# P4.9 — Runtime Attestation Signal Hardening

P4.9 hardens the P4.7 Vercel Drain evidence classifier after Production observation showed Node `DEP0169` from `web-push@3.6.7` arriving from Vercel as `level=error` even though the guest request completed successfully.

## Boundary

This is not a blanket warning/error suppression rule. The receiver ignores only the exact Node lambda diagnostic shape containing `[DEP0169] DeprecationWarning: `url.parse()``, the WHATWG URL guidance, and no HTTP 5xx status.

The following remain blocking evidence exactly as before:
- every other Vercel `error`;
- every `fatal`;
- every HTTP 5xx, including an event that also contains DEP0169 text;
- exact P4.7 smoke markers.

No raw log message is persisted. P4.7 SHA256-only privacy semantics remain unchanged.

## Why not patch `web-push`

The installed stable dependency is `web-push@3.6.7`. P4.9 does not vendor or hand-patch an upstream npm package. The classifier is scoped to the observed diagnostic and can be removed when the stable dependency stops emitting it.

## Certification boundary

P4.9 does not manufacture P2.5 evidence and does not change the P2.5 required-check contract. `runtime_errors` remains pending until a real P2.4 envelope exists and an exact Preview smoke window is observed through P4.8/P4.7 evidence.

No Product Factory tenant is created or activated by P4.9.
