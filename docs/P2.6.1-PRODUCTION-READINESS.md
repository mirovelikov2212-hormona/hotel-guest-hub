# P2.6.1 — Production Readiness Contract

## Purpose

P2.6.1 proves that an exact Product Factory lineage which already passed P2.5 Sandbox certification is safe to enter a later Production publication stage.

It is a readiness gate only. Passing this stage does **not** activate, publish, certify, or expose the Production tenant.

## Preconditions

- exact P2.1 → P2.5 lineage exists and is completed;
- the P2.5 Sandbox certification ledger is `passed`;
- Sandbox is active, linked to the exact Production hotel, healthy/certified, and on the certified revision;
- Production remains inactive and non-sandbox;
- Production public identity remains `reserved`;
- Production health certification remains `pending / not_started`;
- the exact Production revision remains `draft`;
- Production projection state points to that exact revision and has no active routing;
- rooms and departments match Sandbox structurally;
- Production role templates, services, workflows, routing, integrations, reporting, branding, knowledge, and AI permissions remain fail-closed.

## Evidence contract

All of these checks must be `true`:

- `sandbox_certification`
- `tenant_isolation`
- `candidate_build`
- `runtime_errors`
- `supabase_security`
- `guest_runtime_dry_run`
- `staff_runtime_dry_run`
- `rollback_plan`
- `no_production_activation`

The server computes a canonical SHA-256 evidence hash. The database stores the hash and full checks JSON in the immutable readiness ledger.

## Database boundary

`assess_factory_production_readiness_v1` is a service-role-only `SECURITY DEFINER` function with a fixed `search_path`.

The function may insert only:

1. one immutable `factory_production_readiness_runs` row;
2. one Control Plane audit-log row.

It contains no Production activation/publication updates. Before returning it reasserts that Production is still inactive, identity is still reserved, certification is still not started, and the exact revision is still draft.

## Idempotency

The Sandbox certification run is the idempotency key. Replaying the exact same evidence returns the existing readiness run. Different evidence/checks for the same certification run fail with an idempotency conflict.

## Non-goals

P2.6.1 does not:

- activate `hotels.active` for Production;
- change Production public identity to `certified` or `active`;
- publish a config revision;
- enable staff role templates;
- enable services, workflows, routing, integrations, reporting, AI actions, or credentials;
- create a test/fake factory hotel;
- provide a Production activation or publication endpoint.

A later, separately audited stage must consume a valid readiness run before any Production publication can be designed or executed.
