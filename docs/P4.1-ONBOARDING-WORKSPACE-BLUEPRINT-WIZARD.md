# P4.1 — Onboarding Workspace & Blueprint Wizard

P4.1 begins the One-click Hotel Factory operator experience without creating a Product Factory tenant.

## Workspace

Authenticated Platform Admin route:

- `/control-plane/factory/new?lang=bg`
- `/control-plane/factory/new?lang=en`

The visible workflow is bilingual and builds the base version 1 Product Factory blueprint from:

1. organization and hotel identity;
2. country, IANA timezone and arbitrary BCP-47 locale list;
3. room inventory as a numeric range or explicit room list;
4. generic departments, working hours and after-hours targets;
5. review and server-side Product Factory preflight.

## Preflight

`POST /api/control-plane/onboarding/preflight` is same-origin and Platform Admin authenticated. It uses the exact P0/P2 Product Factory validators:

- `prepareFactoryOnboarding`;
- `validateFactoryBlueprint`.

It returns the normalized blueprint hash, future Production/Sandbox identities and structural counts.

It performs no Supabase write and does not call `beginFactoryOnboarding`.

## Deliberate P4.1 boundary

Services, workflows and integrations stay empty in P4.1. P4.2 will add the module/workflow builder before any real onboarding action is exposed.

Therefore P4.1 cannot:

- create a property or hotel;
- create Production/Sandbox environment rows;
- project resources;
- certify Sandbox;
- publish Production;
- activate LIVE;
- start a commercial trial.

This keeps the first operator-facing factory step useful and safe while preserving the exact P0/P2 blueprint authority.
