# P4.2 — Operational Blueprint Builder

Status: **bilingual Services / Workflows / Integrations editing + Product Factory preflight**

## Goal

P4.2 extends the authenticated BG/EN P4.1 Hotel Factory workspace so an operator can describe the hotel's operational model before any tenant is created.

The wizard now has five steps:

1. organization and hotel identity;
2. rooms and locales;
3. departments, operating windows and after-hours targets;
4. services, workflows and credential-free integrations;
5. review and the existing Product Factory preflight.

## Services

Services use the exact P0/P2 Product Factory vocabulary:

- modes: `core`, `configurable`, `custom`;
- priorities: `low`, `normal`, `high`, `urgent`;
- optional references to a declared department, workflow and integration.

A simple service may route directly to a department without requiring a workflow or integration.

## Workflows

Workflow steps are limited to the approved primitive families already supported by the Product Factory model:

- `assign`;
- `condition`;
- `approval`;
- `wait`;
- `billing`;
- `notification`;
- `escalation`;
- `integration_action`;
- `complete`.

Steps may reference only departments and integrations declared in the same in-memory blueprint. The authoritative preflight validates the final references again.

## Integrations

The UI collects only integration identity metadata:

- integration id;
- kind;
- adapter key.

It deliberately exposes no password, token, secret or credential-value field. P2.3 later projects integrations as tenant-scoped placeholders with no live external connection.

## Reference cleanup

Removing a department, workflow or integration clears dependent selections from services and workflow steps. This prevents stale references in normal UI editing while the server-side Product Factory validator remains the final authority.

## Safety boundary

P4.2 still performs no tenant creation or projection. The browser calls only the existing same-origin Platform Admin preflight endpoint. It does not call P2.1 onboarding, P2.2/P2.3 projection, Sandbox certification, Production publication, LIVE activation or commercial lifecycle mutations.

No Supabase migration or new tenant-scoped query is introduced in P4.2.

## Exit criteria

P4.2 is complete when:

- BG/EN five-step wizard builds services/workflows/integrations using the exact Product Factory model;
- integration credentials cannot be collected;
- reference cleanup and server-side preflight both protect relational consistency;
- historical P4.1 safety contracts still pass;
- the full existing suite and P4.2-specific contracts pass;
- tenant-isolation checkpoint is unchanged;
- exact Preview and Production builds are clean;
- no Product Factory tenant or commercial state is created during validation.
