# P3.2 — Commercial Control Plane Operator UI

## Goal

Turn the P3.1 commercial lifecycle API into a safe operator experience inside StayHub Control Plane.

P3.2 does **not** add a second commercial state machine and does **not** write directly to Supabase from the browser. Every operator action uses the existing same-origin P3.1 endpoint:

`POST /api/control-plane/commercial/property-lifecycle`

The database remains the final transition authority.

## Operator flow

Each property card shows technical state and commercial state separately.

Allowed commercial actions are derived from the current P3.1 status:

- `UNMANAGED` → Initialize commercial control
- `PENDING` → Start trial / Convert to customer / End
- `TRIAL` → Extend trial / Convert to customer / Suspend / End
- `ACTIVE_CUSTOMER` → Suspend / End
- `SUSPENDED` → Resume / Convert to customer / End
- `ENDED` → no further actions

The common sales action is **Start 14-day trial**. The operator can change the initial period to any value from 1 to 60 days, matching the P3.1 database contract.

## Safety

Every transition:

1. opens an explicit modal;
2. requires an audit reason;
3. requires an explicit confirmation checkbox;
4. creates a fresh UUID idempotency key in the browser;
5. sends the current commercial `version` for optimistic CAS, except first initialization;
6. calls the same-origin authenticated Control Plane API;
7. refreshes the server-rendered registry only after success.

Actions that grant entitlement (`start_trial`, `convert_to_customer`, `resume`) are disabled in the UI when the property has no active Production environment. The database independently re-checks the same invariant.

No hotel names, slugs, countries or room models are hardcoded in the action logic.

## Important boundary

P3.2 is an operator UI for commercial authority. It does **not** silently change `hotels.active`, technical property lifecycle, routing, credentials or Product Factory certification state.

P3.1 already derives `trial_expired` and `accessAllowed=false` from time. A later enforcement phase will bind that commercial entitlement to guest/staff runtime access with a dedicated fail-safe contract.

This separation is intentional: commercial state can be audited and corrected without using a clock or browser action to directly disable a hotel runtime.
