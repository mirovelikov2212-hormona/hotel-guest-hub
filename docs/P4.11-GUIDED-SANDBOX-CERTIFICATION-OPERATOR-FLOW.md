# P4.11 — Guided Sandbox Certification Operator Flow

## Purpose

P4.11 turns the P4.5 → P4.10 evidence stack into one guided Control Plane workflow for a real Product Factory onboarding run.

It does not introduce a new certification authority. The browser orchestrates the existing P4.8 smoke API and, only after a clean signed window, calls the P4.10 trusted certification bridge.

## Runtime boundary

The workflow is mutation-capable only when the current Control Plane is running on the exact validated Vercel Preview:

- `releaseEvidence.environment = preview`
- `lineageMode = preview_self`
- Factory Release Gate validated
- exact Vercel Preview status validated
- P4.5 database preflight validated
- Production inactive
- Sandbox inactive
- P2.5 certification not started
- current Generic Staff runtime probe validated

On Production, the panel is read-only and explains that smoke/certification must run from the exact Preview deployment.

## Guided smoke

The operator starts one read-only tenant smoke. P4.11 calls only the existing P4.8 endpoint:

1. `start`
2. `settle` until the signed start/end evidence has aged at least 60 seconds
3. `status` until the signed settle marker is visible

The UI treats only `observation.status = observed_clean` as certification-ready. A failed, missing, ambiguous, stale, or cross-lineage window remains blocked.

The browser stores only `smokeRunId` in `sessionStorage` so a page refresh can resume verification. This value is a pointer, not authority: P4.8 and P4.10 revalidate the exact envelope/deployment/project/Git lineage server-side.

## Explicit Sandbox mutation

A clean smoke does not automatically certify Sandbox.

The operator must explicitly confirm that the next action activates **Sandbox only**. The browser then posts only:

- `envelopeProjectionRunId`
- `smokeRunId`

to the existing `/api/control-plane/onboarding/sandbox-certification` route.

P4.10 derives every P2.5 check server-side. No browser-supplied `checks`, `evidence`, deployment ID, project ID, Git SHA, or runtime error boolean is accepted.

## Production boundary

P4.11 does not call any P2.6 transition:

- no Production Readiness
- no dark publication
- no Production runtime certification
- no LIVE activation
- no rollback

A successful P2.5 certification activates the Sandbox according to the existing P2.5 contract and refreshes authoritative state. Production remains inactive.

## Current no-fake-tenant boundary

There are no real Product Factory P2.1–P2.4 onboarding runs at introduction time. The UI and contracts can therefore be validated in Preview, but no smoke or certification is fabricated merely to demonstrate the workflow.
