# P4.5 — Guided Sandbox Certification Preflight

## Status and naming

`P4.5` is a new sequential P4 label introduced after P4.4. It is not a previously historical milestone name.

P4.5 integrates the already-existing P2.5 Sandbox Certification contract into the Product Factory Control Plane in a fail-closed, evidence-driven way. This stage is intentionally read-only: it does not call `certify_factory_sandbox_v1`, does not activate Sandbox, and does not change Production.

## Source-of-truth P2.5 checks

P4.5 follows the current P2.5 implementation rather than older handoff wording. The required certification checks are:

1. `generic_staff_runtime`
2. `tenant_isolation`
3. `preview_build`
4. `runtime_errors`
5. `supabase_security`
6. `integration_placeholders`
7. `reporting_fail_closed`
8. `branding_placeholder`
9. `knowledge_placeholder`

The operator does not submit these as checkboxes and cannot manufacture `true` values.

## Read-only database preflight

Database authority is `get_factory_sandbox_preflight_v1(envelopeProjectionRunId)`.

The RPC is:

- `STABLE`;
- `SECURITY DEFINER`;
- fixed to `search_path = pg_catalog, public`;
- executable only by `service_role` apart from owner authority;
- read-only and exact-lineage bound.

It reconstructs the exact completed P2.4 → P2.3 → P2.2 → P2.1 lineage and verifies the database invariants that P2.5 itself will re-check transactionally:

- exact revision-4 Production/Sandbox draft lineage;
- exact Property environment mappings;
- Production remains inactive and non-sandbox;
- pre-certification Sandbox remains inactive and linked to Production;
- department and manager role templates remain fail-closed;
- services/workflows/routing remain runtime-disabled;
- integrations remain placeholders;
- reporting remains disabled with no recipients;
- branding and knowledge remain placeholders;
- AI permissions remain pending with all actions false;
- public identity and health state remain in the expected pre-certification state;
- the P2.5 certification ledger/RPC preserve their RLS/grant/SECURITY DEFINER boundaries.

If a completed P2.5 certification already exists, the same read RPC switches to the expected post-certification Sandbox state and reads the immutable stored evidence/check result. Production is still required to remain inactive.

## Evidence states

The Control Plane presents three states:

- `pending` — database state is safe, but exact external runtime/build evidence is still missing;
- `failed` — one or more authoritative database gates fail;
- `validated` — an immutable completed P2.5 certification exists and its stored checks remain consistent with the current database safety gates.

Before certification, the following checks require system-generated external evidence and therefore remain `pending` in the database-only layer:

- Generic Staff runtime smoke;
- tenant-isolation code/CI gate;
- exact Vercel Preview build;
- runtime error verification.

Database-derived P2.5 checks are never promoted from operator input.

## Mutation boundary

P4.5 preflight explicitly returns `certificationMutationAvailable=false`.

The existing mutation boundary remains separate:

`POST /api/control-plane/onboarding/sandbox-certification`
→ server authority / exact evidence hashing
→ `certify_factory_sandbox_v1`.

A later guided certification action must re-derive or verify every required external evidence item immediately before that POST. It must not trust client booleans or a stale browser snapshot.

No certification POST is executed during P4.5 implementation because there is currently no real Product Factory P2.1→P2.4 tenant waiting for certification.

## Product Factory safety

P4.5 does not:

- create a fake Product Factory tenant;
- invent a PIN, secret, credential, API key or hotel data;
- activate Sandbox;
- activate or publish Production;
- enable operational runtime resources;
- alter P2.5 certification semantics.

The next implementation step after this read-only layer is a trusted external evidence collector for exact Git/Preview/runtime smoke evidence, followed by a separate explicit certification action only when a real Factory tenant exists.
