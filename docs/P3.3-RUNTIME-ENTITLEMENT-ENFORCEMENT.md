# P3.3 — Production Runtime Entitlement Enforcement

## Goal

Bind the P3 commercial lifecycle to real **Production** Guest, QR and Staff runtime access without mutating technical hotel lifecycle state.

The commercial authority remains separate from Product Factory technical activation. P3.3 is an authorization gate, not a deprovisioning job.

## Runtime decision

For an active hotel runtime:

- no `property_environments` mapping → allow as `legacy_unmanaged`;
- Sandbox or Demo environment → allow as `non_production_bypass`;
- Production with no `property_commercial_state` row → allow as `legacy_unmanaged`;
- managed Production `trial` with `trial_ends_at > database statement time` → allow;
- managed Production `active_customer` → allow;
- managed Production `pending`, expired trial, `suspended`, `ended`, or malformed commercial state → deny.

This preserves all existing tenants until they are explicitly placed under P3 commercial management.

## No cron expiry

Trial expiry is derived at request time from `trial_ends_at`. There is no scheduled mutation that can be missed or delayed.

A 14-day trial therefore stops Production runtime authorization immediately after the deadline on the next request. Converting the same property to `active_customer` restores authorization on the next request without onboarding again.

## Enforcement boundaries

P3.3 enforces the same decision at shared runtime boundaries:

1. `resolveHotelByAnySlugAdmin` for new Production runtime entry points, QR, staff login, massage and guest actions;
2. `getGuestStayAccessState` for already-open Guest history/read-write requests, including legacy routes with their own hotel lookup;
3. `getCurrentStaffSession` for already-open Staff Hub sessions and polling;
4. `/h/[hotelSlug]` checks entitlement before loading tenant config and renders a safe unavailable screen on a commercial denial.

## Recovery remains available

P3.3 does not disable:

- Control Plane;
- Sandbox/Demo environments;
- Product Factory certification/rollback capability;
- configuration data;
- staff credentials;
- guest history;
- technical hotel/property lifecycle rows.

No P3.3 SQL writes commercial or technical state. The runtime entitlement RPC is stable/read-only and service-role-only.

## Legacy safety

Aquamarine and every existing property with no commercial row remain allowed. P3.3 does not backfill `property_commercial_state` and does not invoke P3.1 transitions during validation.

## Performance note

The first version favors exact commercial correctness and immediate reversibility over a stale cache. The entitlement RPC uses indexed one-to-one lookups (`property_environments.hotel_id` unique and `property_commercial_state.property_id` primary key).

If production telemetry later shows meaningful overhead at large scale, Staff heartbeat/session authorization can be coalesced with the entitlement read without weakening the commercial authority contract.
